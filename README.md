# Marshrutka

Окно в конвейеры. Пять страниц, никакой логики.

Управление живёт в Hermes: он ведёт суточный прогон, публикует, разбирает
падения. Маршрутка нужна для того, что в чате делать неудобно — окинуть
взглядом состояние, положить в инбокс десяток ссылок разом, посмотреть, на
каком шаге упал прогон.

```
браузер ──> marshrutka :8100 ──HTTP──> youtube-pipelines :8010 ──> конвейеры
            (отдельный сервер)          (сервер с конвейерами)
```

## Страницы

| Путь | Что показывает |
|---|---|
| `/` | Здоровье трёх конвейеров, счётчики, последние прогоны |
| `/inbox` | Что ждёт крона, форма добавления, возврат зависших |
| `/history` | Что уже брали, ссылки на опубликованное, кнопка «забыть» |
| `/runs/{project}` | Прогоны с конвейера, фильтр по статусу |
| `/runs/{project}/{job_id}` | Шаги, ошибки, артефакты одного прогона |

## Чего здесь нет намеренно

- **Секретов каналов.** Креды YouTube лежат на сервере с конвейерами, UI их
  не получает даже на чтение — `/api/profiles` отдаёт только названия и флаг
  готовности OAuth.
- **Кнопки «опубликовать».** Публикация тратит 1600 единиц квоты и уходит на
  живой канал. Это делает Hermes по скиллу, а не человек одним кликом.
- **Кнопки «запустить».** Прогон запускает крон, забирая верхний элемент
  инбокса. Хочешь запустить сейчас — скажи Hermes в Telegram.
- **Своей базы.** Вся история и инбокс живут рядом с конвейерами. Маршрутку
  можно снести и поднять заново, ничего не потеряв.

## Запуск

```bash
cp .env.example .env      # прописать HP_API_URL и HP_API_TOKEN
docker compose up -d --build
curl -s localhost:8100/health
```

Локально без докера:

```bash
pip install -r requirements.txt
HP_API_URL=http://141.136.44.9:8010 HP_API_TOKEN=... uvicorn main:app --reload --port 8100
```

## Что осталось от прежней версии

Логотипы и фавиконки в `static/`, палитра и формы элементов — продукт должен
остаться узнаваемым. Всё остальное вырезано вместе со своими страницами:
очередь, планировщик, CRUD проектов, публикация, встроенный агент.
