# Передача работы: продолжение на другой машине

Всё, что нужно, чтобы поднять проект с нуля на новом компьютере с VS Code +
Claude и довести до работающего суточного прогона.

Читать по порядку. Промпты — копипастить в панель Claude целиком.

---

## 0. Где мы находимся

**Что сделано:**

- Все три конвейера переведены с SaluteSpeech на ElevenLabs. SaluteSpeech
  закрыл сервис синтеза — без этой правки ни один конвейер не соберёт видео.
- Написан `hermes-pipelines`: MCP-слой между Hermes и конвейерами, история с
  защитой от дублей, инбокс, публикация на YouTube, HTTP API для UI.
- Написана новая маршрутка: 5 страниц вместо 13, без базы и без секретов.
- Документация во всех репозиториях обновлена.

**Что не сделано и почему:** ничего не задеплоено и не проверено на живых
сервисах. Среда, где всё это готовилось, — облачная песочница без SSH-ключей и
с закрытой сетью до `141.136.44.9`. Поэтому следующий шаг — твоя машина.

**Что решать тебе, а не агенту:** всё, что связано с аккаунтами Google
(перевод OAuth consent screen в Production, YouTube API audit, повторная
авторизация каналов в браузере) и выбор каналов-доноров для скаута.

## 1. На старом компьютере: один промпт

Открой Claude в VS Code в папке, где лежат все четыре проекта, и дай ему
`PUSH_PROMPT.md` — он закоммитит и запушит всё, что накопилось.

Отдельно, **не через git**: `.env` файлы в репозитории не попадают. Либо
скопируй их на новую машину сам, либо забери с сервера:

```bash
scp root@141.136.44.9:/opt/ezhu-ponyatno/.env  ~/ezhu-ponyatno/.env
scp root@141.136.44.9:/opt/story-to-video/.env ~/story-to-video/.env
scp root@141.136.44.9:/opt/zad-pegasa/.env     ~/zad-pegasa/.env
```

Учти: в серверных `.env` пока нет ни `API_KEY`, ни блока ElevenLabs для
ежу-понятно — их добавит задача 2. Локальные `.env` на старой машине уже
поправлены, так что проще перенести именно их.

Ещё понадобится на новой машине: SSH-ключ, которым ты ходишь на
`root@141.136.44.9`, и залогиненный `gh` либо доступ к GitHub.

## 2. На новом компьютере: подготовка

```bash
mkdir -p ~/work && cd ~/work
git clone https://github.com/frtsvnth/ezhu-ponyatno.git
git clone https://github.com/frtsvnth/news-to-video.git story-to-video
git clone https://github.com/frtsvnth/zad-pegasa
git clone https://github.com/frtsvnth/marshrutka.git
git clone https://github.com/frtsvnth/hermes-pipelines.git

ssh root@141.136.44.9 'echo ok'      # ключ на месте?
```

**Claude Code не читает `AGENTS.md`** — только `CLAUDE.md`. Твои правила из
`AGENTS.md` расширение просто не увидит, пока не сделаешь:

```bash
cd ~/work
for d in ezhu-ponyatno story-to-video zad-pegasa marshrutka hermes-pipelines; do
  cp AGENTS.md "$d/AGENTS.md" 2>/dev/null
  ln -sf AGENTS.md "$d/CLAUDE.md"
done
```

Проверить в сессии: `/context`, там должен появиться `CLAUDE.md` под
**Memory files**.

Расширение стартует в режиме Auto — классификатор проверяет действия вместо
тебя. Для деплойных задач это нормально; если хочешь видеть каждую команду,
переключи на Manual внизу поля ввода.

## 3. Задача 1 — закрыть API ключом

**Делать первой.** Сейчас конвейеры открыты интернету: любой, кто знает адрес,
может запускать прогоны за твой счёт.

```
Проверь, открыты ли API конвейеров наружу:

curl -s -o /dev/null -w '%{http_code}\n' http://141.136.44.9:8000/jobs
curl -s -o /dev/null -w '%{http_code}\n' http://141.136.44.9:8001/jobs
curl -s -o /dev/null -w '%{http_code}\n' http://141.136.44.9:8002/jobs

Если не 401 — сгенерируй один длинный ключ, добавь строку API_KEY=<ключ> в .env
каждого из трёх проектов на сервере (/opt/ezhu-ponyatno, /opt/story-to-video,
/opt/zad-pegasa), перезапусти через docker compose up -d и убедись, что снаружи
стало 401, а с заголовком X-API-Key всё работает.

Ключ покажи мне — он понадобится дальше как HP_PIPELINES_API_KEY.

Порты в docker-compose.yml пока не трогай, предложи это отдельно.
```

## 4. Задача 2 — проверить ElevenLabs и задеплоить

Правки уже в репозиториях. Нужно убедиться, что звук нормальный, и раскатать.

```
В репозиториях ezhu-ponyatno и zad-pegasa уже лежат правки перехода с
SaluteSpeech на ElevenLabs. Проверь их и задеплой.

1. Прочитай git log последнего коммита в обоих репозиториях, разберись, что
   изменено.

2. Локально проверь синтез в ежу-понятно:
   python -c "from steps.tts import generate_test_tts; generate_test_tts('Проверка синтеза речи через ElevenLabs.', '/tmp/tts_check.wav')"
   ffprobe -v error -show_entries stream=codec_name,sample_rate,channels -of default=nk=1 /tmp/tts_check.wav
   Ожидается pcm_s16le / 24000 / 1. Дай мне послушать файл.

3. Прогони пайплайн ежу-понятно целиком на коротком видео. Главное, на что
   смотреть: шаги tts и transcribe зелёные, а субтитры попадают в тайминги.
   У ElevenLabs другая интонация и другие паузы — если выравнивание поедет,
   чинить надо шаг subtitles, а не TTS.

4. То же для zad-pegasa.

5. Задеплой: git pull на сервере, затем ОБЯЗАТЕЛЬНО дополни .env вручную —
   через git он не едет. В /opt/ezhu-ponyatno/.env нужен блок ElevenLabs
   (см. .env.example), в /opt/zad-pegasa/.env — TTS_MODE=elevenlabs.
   Только после этого docker compose up -d --build.

6. Проверь логи и /health всех трёх сервисов.
```

## 5. Задача 3 — развернуть hermes-pipelines

```
Разверни hermes-pipelines на сервер с конвейерами по инструкции DEPLOY.md
внутри репозитория.

Учти, чего никто не проверял на живых сервисах:
- pipelines_mcp/web.py писался без возможности запустить fastapi, синтаксис
  проверен, поведение нет — пройди по эндпоинтам руками;
- чанковая resumable-загрузка в youtube.py написана заново вместо старой
  «весь файл одним PUT», докачку по Range на живом обрыве не проверяли;
- вообще ничего не тестировалось против настоящих конвейеров.

Порядок:
1. Клон в /opt/hermes-pipelines, venv, зависимости.
2. .env: HP_PIPELINES_API_KEY из задачи 1, HP_WEB_TOKEN — новый длинный токен.
3. Профили публикации: scripts/migrate_profiles.py забирает их из
   marshrutka/data/publish_profiles.json. Переносить scp, не через git —
   там секреты. Права 0600.
4. scripts/smoke_test.py --youtube
5. scripts/smoke_test.py --run-ezhu <ссылка на короткое видео>
6. systemd-юнит для HTTP API на порту 8010, готовый есть в DEPLOY.md.

Скрипт migrate_profiles.py вынесет из поля notes VK-токен, лежащий там
открытым текстом. Покажи его мне — отзову и выпущу заново.
```

**Про токены YouTube.** У всех трёх профилей `expires_at` датирован июнем, а
Google отзывает refresh-токены каждые 7 дней, пока OAuth consent screen в
статусе Testing. Они почти наверняка мертвы, и это чинится не агентом:

1. [Google Cloud Console](https://console.cloud.google.com/) → OAuth consent
   screen → **Publish app**, статус должен стать Production.
2. Проверить, что в Authorized redirect URIs есть
   `http://localhost:9090/publish/youtube/callback`.
3. Локально, где есть браузер: `python scripts/reauth_youtube.py pub_8d082103`
4. Скопировать обновлённый `publish_profiles.json` на сервер.

Заодно подай на **YouTube API audit**: пока приложение не верифицировано,
залитые через API ролики помечаются *locked as private*, что бы ты ни передал
в `privacyStatus`. Это зреет неделями, поэтому подавайся сразу.

## 6. Задача 4 — подключить Hermes

```
Подключи hermes-pipelines к Hermes на сервере.

1. Скиллы: cp -r /opt/hermes-pipelines/hermes/skills/video/ezhu-daily ~/.hermes/skills/video/
2. Конфиг: блоки из hermes/config-snippets.yaml в ~/.hermes/config.yaml.

   Не пропусти timeout: 3900 у MCP-сервера. Тул pipeline_wait держит вызов всё
   время рендера, 20-40 минут. При дефолтных 300 секундах Hermes оборвёт его на
   середине, и прогон будет выглядеть упавшим, хотя видео собирается.

3. HP_PIPELINES_API_KEY в ~/.hermes/.env
4. /reload-mcp, затем проверка руками, без крона:
     покажи pipelines_list
     добавь в инбокс ежу вот это видео: <ссылка>
     /ezhu-daily

Крон не включай, пока ручной прогон не дойдёт до опубликованного ролика.
```

Модели уже проставлены: `deepseek/deepseek-v4-pro` для агента и цепочек,
`deepseek/deepseek-v4-flash-0731` для субагентов и сводок.

Что проверить: шаблоны рендерятся на синтетических данных, но против живого

Отдельно — форма инбокса: она переключает поле ввода по выбранному проекту

И обратный случай: когда hermes-pipelines недоступен, страницы должны
показывать понятную ошибку, а /health маршрутки — продолжать отвечать ok.

Три вещи в новой маршрутке отсутствуют намеренно, не добавляй их без разговора
со мной: кнопки «опубликовать» и «запустить», и креды каналов.

## 8. Задача 6 — включить расписание

Только после того, как ручной `/ezhu-daily` дошёл до опубликованного ролика.

```
hermes cron create \
  --schedule "0 6 * * *" \
  --skill ezhu-daily \
  --model "deepseek/deepseek-v4-pro" \
  --deliver telegram \
  --prompt "Выполни суточный прогон Ежу Понятно. Если инбокс пуст — просто скажи об этом."
```

`0 6 * * *` в UTC — это 9:00 МСК. Проверить: `hermes cron list`, разовый
запуск: `hermes cron run <job_id>`.

## 10. Что дальше, когда всё поедет

- **Пегас и story-to-video**: тот же скилл, скопированный и поправленный —
  другой проект, другой профиль, свой раздел про требования к тексту. Слой их
  уже знает, код трогать не придётся.
- **Скаут для ежу**: список каналов-доноров и обход их uploads-плейлистов через
  `playlistItems.list` — 1 единица квоты против 100 у `search.list`. Скаут
  станет вторым источником `inbox_add`, менять ничего не нужно.
- **Квота YouTube**: 10 000 единиц в сутки на проект Google Cloud, одна
  публикация стоит 1600. При одном ролике в день запас шестикратный. Станет
  тесно, когда включится скаут — тогда заводить отдельный GCP-проект на канал.

Архитектура и обоснования решений — в артефакте «Диспетчерская Гермеса»
(claude.ai, раздел артефактов). Подробный разбор задач для агента-кодера —
в `CODER_PROMPT.md`.
