## Контекст в двух абзацах

SaluteSpeech закрыл синтез речи, поэтому все три конвейера переведены на
ElevenLabs. Управление конвейерами переезжает с локальной «маршрутки» на агента
Hermes: раз в сутки крон Hermes прогоняет один пайплайн от ссылки до публикации
на YouTube. Между Hermes и конвейерами появляется тонкий слой `hermes-pipelines`
— MCP-сервер плюс HTTP API.

Маршрутка перестаёт быть системой управления и становится окном: дашборд,
инбокс, история, прогоны. Ни базы, ни секретов, ни планировщика у неё больше нет.

## Задача 1. Проверить и закоммитить правки TTS

### Что уже изменено локально

**`ezhu-ponyatno`** — ElevenLabs там не было вообще, добавлен провайдер:

- `steps/tts.py` — функции `get_provider()` и `resolve_voice()`,
  `_elevenlabs_synthesize()`, роутинг в `synthesize_text(..., provider=)`.
  Токен Сбера запрашивается только при `TTS_PROVIDER=salutespeech`.
- `app/config.py` — в `TtsConfig` добавлено поле `provider`; валидация голосов
  Сбера теперь применяется только к Сберу.
- `api.py` — в `JobRequest` добавлен `tts_provider`, проброшен в `TtsConfig`.
- `config_defaults.json` — `tts_provider: elevenlabs`, `voice` заменён на
  ElevenLabs voice_id, `use_ssml: false`.
- `steps/metadata_package.py` — id модели поправлен на
  `deepseek/deepseek-v4-flash-0731`, вынесен в env `METADATA_MODEL`.
- `.env` — добавлен блок ElevenLabs, ключ взят из `zad-pegasa/.env`.
  Резервная копия: `.env.bak-tts`.

**`zad-pegasa`** — ElevenLabs был реализован, переключены умолчания:

- `config.py` — `TtsConfig.mode` по умолчанию `elevenlabs`.
- `steps/tts.py` — фолбэк `cfg.mode or "elevenlabs"`, обновлён docstring.
- `config_defaults.json`, `.env`, `.env.example` — `TTS_MODE=elevenlabs`.

**`story-to-video`** — не трогали: там уже `TTS_PROVIDER=elevenlabs` в `.env`,
в `config_defaults.json` и в дефолте `app/config.py`.

### Что проверено

Логика ElevenLabs в ежу прогнана на замоканном HTTP: WAV на выходе получается
24000 Гц, моно, 16 бит — тот же формат, что отдавал SaluteSpeech, поэтому
`ffmpeg concat -c copy` и Whisper ниже по конвейеру работают без изменений.
Проверено, что скорость речи не задаётся дважды: ElevenLabs синтезирует на 1.0,
`speech_rate` применяется через `atempo`, как и раньше.

### Что проверить тебе

1. `git diff` в обоих репозиториях — правки должны быть ровно те, что описаны.
2. Живой синтез. Ключ ElevenLabs в `.env` есть, лимит символов — нет:

   ```bash
   cd ezhu-ponyatno && source .venv/bin/activate
   python -c "
   from steps.tts import generate_test_tts
   generate_test_tts('Проверка синтеза речи через ElevenLabs.', '/tmp/tts_check.wav')
   "
   ffprobe -v error -show_entries stream=codec_name,sample_rate,channels -of default=nk=1 /tmp/tts_check.wav
   ```

   Ждём `pcm_s16le / 24000 / 1`. Послушать файл — русский должен звучать
   нормально, без обрубленных окончаний.

3. Прогнать пайплайн ежу целиком на коротком видео и убедиться, что шаги
   `tts` и `transcribe` зелёные, а субтитры попадают в тайминги. Это главный
   риск смены провайдера: интонация и паузы у ElevenLabs другие, и если
   выравнивание субтитров поедет — чинить надо там, а не в TTS.

4. Тот же прогон для `zad-pegasa`.

5. Коммит и деплой:

   ```bash
   git add -A && git commit -m "tts: перевод на ElevenLabs, SaluteSpeech закрыл сервис"
   git push
   ssh root@141.136.44.9 'cd /opt/ezhu-ponyatno && git pull'
   ```

   **`.env` через git не едет.** На сервере в `/opt/ezhu-ponyatno/.env` нужно
   руками добавить блок ElevenLabs (см. `.env.example`), а в
   `/opt/zad-pegasa/.env` поменять `TTS_MODE`. Только после этого
   `docker compose up -d --build`.

6. Проверить после рестарта: `docker logs --tail 100 ezhu_api`, затем прогон
   через API и `curl /health` всех трёх.

## Задача 2. Закрыть API конвейеров ключом

**Это важнее всего остального, сделай первым.** Сейчас ни в одном из трёх
`.env` нет `API_KEY`, а порты в `docker-compose.yml` опубликованы на `0.0.0.0`.
Любой человек, знающий адрес, может дёргать `POST /jobs` и тратить кредиты
ElevenLabs, routerai и Pexels.

Проверка снаружи, с машины, отличной от сервера:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://141.136.44.9:8000/jobs
```

Не `401` — значит открыто.

Что сделать:

1. Сгенерировать один длинный ключ на все три конвейера.
2. Добавить `API_KEY=<ключ>` в `.env` каждого проекта на сервере, `docker compose up -d`.
3. Убедиться, что снаружи стало `401`, а с ключом — работает.
4. Этот же ключ пойдёт в `HP_PIPELINES_API_KEY` для `hermes-pipelines`.

Отдельно предложи пользователю (не делай без подтверждения) закрыть порты
конвейеров от внешнего мира совсем — заменить в каждом `docker-compose.yml`:

```yaml
ports:
  - "127.0.0.1:${API_PORT:-8000}:8000"
```

После этого снаружи их не видно, а `hermes-pipelines` с того же хоста работает
как работал. Единственный порт наружу останется 8010 — HTTP API для UI.

## Задача 3. Развернуть hermes-pipelines

Код лежит в `marshrutka/hermes-pipelines/`. Его надо вынести в отдельный
репозиторий и поставить на сервер конвейеров. Полная инструкция — в
`DEPLOY.md` внутри проекта, здесь только то, что требует внимания.

**Что это.** MCP-сервер (18 тулов) плюс HTTP API поверх тех же данных.
Работает по stdio — Hermes запускает его сам как дочерний процесс, порт ему
не нужен. HTTP API (`pipelines_mcp.web`) — отдельный процесс на 8010, нужен
только для UI.

**Что проверено:** цепочка `run → wait → metadata → fetch → publish → cleanup`
прогнана против мок-конвейера целиком, включая ветки «дубль», «partial»,
«сервис недоступен», «пустой payload». Нормализация ключей дедупликации и
инбокс покрыты тестами.

**Что НЕ проверено и требует твоих глаз:**

- `pipelines_mcp/web.py` — писался без возможности запустить `fastapi`
  (в песочнице не было доступа к PyPI). Синтаксис проверен, поведение — нет.
  Подними и пройди по эндпоинтам руками.
- `pipelines_mcp/youtube.py` — чанковая resumable-загрузка написана заново
  вместо старой «весь файл одним PUT». Логику докачки по `Range` на живом
  обрыве связи никто не проверял.
- Ничего из этого не тестировалось против настоящих конвейеров: из среды, где
  готовился код, сеть до `141.136.44.9` закрыта.

**Порядок:**

1. Репозиторий, `git clone` в `/opt/hermes-pipelines`, venv, зависимости.
2. `.env` по образцу `.env.example`: `HP_PIPELINES_API_KEY` из задачи 2,
   `HP_WEB_TOKEN` — новый длинный токен для UI.
3. Профили публикации: `scripts/migrate_profiles.py` забирает их из
   `marshrutka/data/publish_profiles.json`. Переносится не через git — там
   секреты, копировать `scp` в `/root/.hermes-pipelines/`, права `0600`.
4. `scripts/smoke_test.py --youtube` — проверка конвейеров и токенов каналов.
5. `scripts/smoke_test.py --run-ezhu <ссылка>` — полный прогон без публикации.
6. systemd-юнит для HTTP API (готовый есть в `DEPLOY.md`), порт 8010.

**Про токены YouTube.** У всех трёх профилей `expires_at` датирован июнем, а
Google отзывает refresh-токены каждые 7 дней, пока OAuth consent screen в
статусе Testing. Токены почти наверняка мертвы. Порядок: consent screen в
Production, затем `scripts/reauth_youtube.py pub_8d082103` — запускать
**локально**, нужен браузер и свободный порт 9090. Это задача пользователя,
не твоя: тебе нужно только проверить результат через `smoke_test.py --youtube`.

## Задача 4. Перекроить и развернуть маршрутку

Новая версия лежит в `marshrutka/marshrutka-ui/`. Это не патч поверх старой —
90% прежнего кода реализовывало то, что мы удаляем, поэтому проще собрать
заново, чем вырезать.

**Что осталось от прежней версии:** логотипы и фавиконки в `static/`, палитра
и формы элементов (перенесены из `templates/base.html` в `static/app.css` без
изменения цветов). Продукт должен остаться узнаваемым.

**Что удалить из репозитория маршрутки:**

```
agent/            встроенный агент — его работу делает Hermes
templates/        кроме тех, что в новой версии
ui.py             47 KB, страницы удалённых разделов
api.py            REST старой очереди
models.py registry.py runner.py scheduler.py storage.py remote_sync.py
youtube_adapter.py    перенесён в hermes-pipelines
projects/ data/   реестр и состояние переехали
main.py config.py заменены новыми
```

Оставить и перенести в корень: содержимое `marshrutka-ui/`.
Файлы `hermes-pipelines.zip`, `_archive.zip`, `_old-hermes-migration/`,
`hermes-migration.zip` — мусор, удалить.

**Важно, что в новой маршрутке отсутствует намеренно:**

- Кнопки «опубликовать» — публикация тратит 1600 единиц квоты и уходит на
  живой канал. Это делает Hermes по скиллу, а не человек одним кликом.
- Кнопки «запустить» — прогон запускает крон, забирая верхний элемент инбокса.
- Креды каналов — `/api/profiles` отдаёт только названия и флаг готовности
  OAuth. На UI-сервере секретов быть не должно вообще.

Если будешь добавлять что-то по ходу — эти три пункта не трогай без разговора
с пользователем.

**Деплой:** отдельный сервер, `docker compose up -d --build`, порт 8100
(конвенция UI 8100-8199). В `.env` — `HP_API_URL=http://141.136.44.9:8010` и
`HP_API_TOKEN` = `HP_WEB_TOKEN` из задачи 3.

**Что проверить:** шаблоны рендерятся (проверено на синтетических данных), но
против живого API не гонялись. Пройди все пять страниц. Отдельно: форма инбокса
переключает поле ввода по выбранному проекту через JS и отключает скрытые
`input`/`textarea` — иначе в POST уедут два значения `name="value"`. Убедись,
что после переключения проекта отправляется ровно одно.

Проверь и обратный случай: когда `hermes-pipelines` недоступен, страницы должны
показывать понятную ошибку, а `/health` маршрутки — продолжать отвечать `ok`.

## Задача 5. Подключить Hermes

Hermes уже стоит на сервере конвейеров.

1. Скиллы: `cp -r /opt/hermes-pipelines/hermes/skills/video/ezhu-daily ~/.hermes/skills/video/`
2. Конфиг: блоки из `hermes/config-snippets.yaml` в `~/.hermes/config.yaml`.

   **Не пропусти `timeout: 3900` у MCP-сервера.** Тул `pipeline_wait` держит
   вызов всё время рендера, 20–40 минут. При дефолтных 300 секундах Hermes
   оборвёт его на середине, и прогон будет выглядеть упавшим, хотя видео
   собирается.

3. `HP_PIPELINES_API_KEY` в `~/.hermes/.env`.
4. `/reload-mcp`, затем проверка руками, без крона:
   ```
   покажи pipelines_list
   добавь в инбокс ежу вот это видео: <ссылка>
   /ezhu-daily
   ```
5. Крон включать **только после** того, как ручной прогон дошёл до
   опубликованного ролика. Команда — в `config-snippets.yaml`.

Модели routerai уже проставлены точными id: `deepseek/deepseek-v4-pro` для
агента и цепочек, `deepseek/deepseek-v4-flash-0731` для субагентов и сводок.
